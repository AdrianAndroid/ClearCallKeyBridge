# 精简为"三键单击"（面向 V98）

## 背景

V98（可用设备）只有 3 个物理键，且日志通道只能给出**命令级**信号，没有 release 事件：

- 播放/暂停（一个键，交替发 Play / Pause）
- 音量 +
- 音量 −

此前的界面按 ClearCall 200 的 4 键 × 多手势设计（静音键、通话键双击/长按、音量 + 长按），
在 V98 上全部无法产生，属于"能配但不能触发"的无效项。用户要求：**去掉静音键，三个键只保留单击**。

本次同时撤销"冒充 Now Playing 接管媒体键"的尝试：实测原型会让系统认为本机有一个静音播放器，
对用户无实际收益（该键本来就不是本程序专属），因此不纳入产品。

## 决策

1. `KEY_LAYOUT` 精简为 3 张卡：通话键（= 播放/暂停）、音量 +、音量 −，每张仅"单击"手势。
2. 默认规则精简为 3 条：`call:click` / `volp:click` / `volm:click`。
3. 静音键（`mute:click`）、`call:double`、`call:long`、`volp:long` 从界面与默认配置移除；
   规范层仍保留这些触发器**定义**（供其它设备将来使用），只是不再出现在 V98 界面与默认规则里。
4. 不引入静音音频会话、不改系统媒体键路由、不做 Now Playing 冒充。

## ADDED Requirements

### Requirement: 三键单击界面
- 界面只展示 3 张按键卡，每卡只含"单击"一行。
- 任何卡片不带双击/长按行，避免用户配置了永远无法触发的项。

#### Scenario: 按下音量 +
- 当 V98 音量通知上升
- 那么 触发 `volp:click`，音量 + 卡亮起

#### Scenario: 按下播放/暂停
- 当 收到 AVRCP Play 或 Pause
- 那么 触发 `call:click`（同一张卡），不额外触发 `call:double`

### Requirement: 不接管系统媒体键
- 本程序不得为"阻止 Music 启动"而常驻静音音频会话或冒充 Now Playing 应用。
- 系统对 AVRCP 命令的原生处理照常发生，界面与文档不得声称已拦截。
