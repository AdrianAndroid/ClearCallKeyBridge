# V98 只读日志检测通道

## 背景 / 动机

2026-11-19 实测（见 `docs/V98按键监听交接.md`）：在移除诊断描述文件、普通用户权限下，
`/usr/bin/log stream` 谓词过滤 `bluetoothd` 时可实时读到 V98（地址 `41:42:DF:39:9A:BE`）
上报的两类消息：AVRCP Play/Pause 命令、绝对音量通知。负向测试（键盘媒体键）0 条捕获，
设备隔离成立。这是目前唯一可区分设备来源的 V98 按键观测通道。

需要把该通道以"只读检测"形式接入程序：先只展示原始检测事件，不执行映射动作；
日志监听**不是拦截**，也不是通用蓝牙协议 API，界面与文档不得夸大。

## 影响面

- 涉及 capability：device-input / terminal-ui / key-mapping（仅配置节）
- 涉及模块与文件：`clearcall200/v98_log.py`（新增）、`clearcall200/app.py`、
  `clearcall200/__main__.py`、`clearcall200/config.py`、`clearcall200/widget.py`、
  `clearcall200/ui_gui.py`、`tests/test_v98_log.py`（新增）
- 不影响 ClearCall 200 的既有触发源清单与规则表；不新增 trigger。

## 规范变更

## ADDED Requirements

### Requirement: V98 日志检测通道（只读）
程序可通过 `log stream` 子进程只读检测已配置地址设备的 AVRCP Play/Pause 命令与
绝对音量通知；检测输出仅作为原始事件展示，不进入规则匹配，不执行动作。

#### Scenario: 检测到播放命令
- 当 bluetoothd 日志出现 `Received AVRCP Play command from device <已配置地址>`
- 那么 界面事件流出现 `DETECT v98 play`，不触发任何 trigger / 动作

#### Scenario: 检测到绝对音量通知
- 当 日志出现 `Received notification for absolute volume 0xXX (~N%) from device <已配置地址>`
- 那么 界面事件流出现 `DETECT v98 volume=0xXX (~N%)`；同值重复与交错如实展示，不做方向判定

### Requirement: 地址过滤与设备隔离
解析层必须再次按目标地址过滤（谓词之外的第二道防线）；地址来自配置
（`capture.v98_log.address`，缺省回退 `device` 字段），不得硬编码。
谓词与解析只处理已验证的两类消息，其他行一律忽略。

#### Scenario: 非目标设备的消息
- 当 日志行携带其他设备地址或不包含地址
- 那么 该行被丢弃，不产生检测事件

### Requirement: 可用状态与降级
通道有明确状态：`disabled`（未启用）/ `starting` / `running` / `unavailable`。
未配置地址、子进程启动失败、流提前结束都必须显示为不可用，不得误判为成功；
子进程退出或程序退出时必须清理（terminate），不得阻塞 UI。

#### Scenario: 未启用
- 当 配置 `capture.v98_log.enabled` 为 false 且未显式请求开启
- 那么 通道不启动，界面提示监听未接入，不产生事件

#### Scenario: 启动失败
- 当 `log stream` 无法启动（子进程报错退出）
- 那么 状态为 `unavailable`，界面出现 `ERR V98 log detect unavailable: <原因>`，不重试轰炸

## MODIFIED Requirements

### Requirement: 采集来源边界（V98 设备隔离，沿用 2026-11-19-v98-isolation.md）
（原文约束不变，补充：）日志检测通道属只读旁听，允许在普通权限下运行；
它仍然不是拦截：系统对同一命令的处理（如唤起音乐 App）照常发生。

## REMOVED Requirements

（无）

## 兼容性

- 配置新增 `capture.v98_log = {enabled, address}`，默认 `enabled=false`，老配置自动补默认值，无需迁移。
- 不改动触发源清单、规则表、动作集合；learn 模式与映射行为均不受影响。

## 代码落地清单

- 新增 `clearcall200/v98_log.py`：`parse_log_line()`（纯函数，可单测）+ `V98LogWatcher`（子进程 + 读线程 + 队列 + 状态机）。
- `app.py`：`attach_v98_log()` / `pump_v98_log()` / 清理；交互、挂件、桌面三种模式接入 pump。
- `widget.py` / `ui_gui.py`：tick 内追加 `pump_v98_log()`。
- `__main__.py`：新增 `--v98-log`（会话级强制开启，仅展示检测事件）。
- 测试：`tests/test_v98_log.py` 覆盖消息解析、地址过滤、无关行忽略、地址校验。
