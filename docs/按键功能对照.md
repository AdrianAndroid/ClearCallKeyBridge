# ClearCall 200 按键功能对照（官方说明书整理 + macOS 实测口径）

> 来源：漫步者 ClearCall 200 官方操作说明（产品页图片）+ 本机 macOS 15.7.9 实测。
> 整理日期：2026-11-19。本文件是驱动的**权威按键口径**，改映射前先看这里。

## 1. 物理按键（共 4 颗，均在左耳侧）

```
        ┌──────────── 左耳罩侧 ────────────┐
        │  ◉ 电源键（带绿色指示灯）          │  ← 最上一颗，圆形带灯
        │  ▭ + 键（拨动/按压，上）           │  ← 音量加
        │  ▭ − 键（拨动/按压，下）           │  ← 音量减
        │  ● 通话键（最下一颗，圆形）        │  ← 接听/挂断/通话控制
        └──────────────────────────────────┘
```

**重要纠正**：说明书里**没有独立的"静音键"**。通话中的静音开关 = **电源键单击**。
早期文档里写的"静音键"是对硬件的误判，实际是电源键在通话状态下的行为。

## 2. 各键功能表（官方定义）

### 电源键

| 状态 | 操作 | 功能 |
|---|---|---|
| 非通话 | 单击 | 暂停 / 播放 |
| 非通话 | 双击 | 唤起语音助手 |
| 通话中 | 单击 | MUTE 开 / 关 |

### ＋ 键

| 状态 | 操作 | 功能 |
|---|---|---|
| 任意 | 单击 | 音量 + |
| 任意 | 长按 | 上一曲 |

### − 键

| 状态 | 操作 | 功能 |
|---|---|---|
| 任意 | 单击 | 音量 − |
| 任意 | 长按 | 下一曲 |

### 通话键

| 场景 | 操作 | 功能 |
|---|---|---|
| 来电 | 单击 | 接听 / 挂断 |
| 来电 | 长按 2 秒 | 拒接来电 |
| 空闲 | 双击 | 电话回拨（最近一通） |
| 通话一拖二（A 通话中，B 来电） | 单击 | 接听 B，A 保持 |
| 通话一拖二 | 双击 | 接听 B，A 挂断 |
| 通话一拖二 | 长按 2 秒 | 拒接 B |
| 接听 B、A 保持中 | 双击 | A 与 B 之间切换 |

## 4. macOS 侧可观测性（决定哪些键能自定义）

| 按键行为 | 底层通道 | macOS 能否观测 | 能否被驱动接管 |
|---|---|---|---|
| ＋ / − 单击（音量） | AVRCP 绝对音量 → 直接写 CoreAudio 输出音量 | **间接可观测**：系统输出音量被改动，但**不产生任何按键事件** | ✅ 可（观测音量变化 → 判定方向 → 写回原值，等效拦截） |
| ＋ / − 长按（上一曲 / 下一曲） | AVRCP Next / Previous 透传 | 取决于当前是否有媒体会话；无事件 tap 抓到记录 | ⚠️ 待验证（需要媒体会话存在） |
| 电源键 单击（播放/暂停） | AVRCP Play / Pause 透传 | 未观测到 NX_SYSDEFINED 事件 | ⚠️ 待验证（可能需借"正在播放"状态变化间接识别） |
| 电源键 双击（语音助手） | 厂商私有（多为 HFP/AT 或本地行为） | 未观测到 | ❌ 目前不可接管 |
| 通话中 电源键单击（MUTE） | HFP 通话控制 | 仅在 HFP 通话态存在 | ❌ 系统独占（本程序无通话 API） |
| 通话键 全部手势 | HFP AT 命令（接听/挂断/拒接/回拨/三方通话） | 非通话状态**完全无事件** | ❌ 系统独占 |

**实测数据支撑**（2026-11-19）：

- CGEventTap（`kCGHIDEventTap` + `kCGSessionEventTap` 双 tap，只收 `type=14`）在耳机按键时**0 条事件**；抓到的 `subtype=7 data1=0x1` 均为鼠标点击。
- `ioreg -c IOHIDDevice`：**无 EDIFIER 任何 HID 节点**。
- `system_profiler SPBluetoothDataType`：`Minor Type: Headset`，`Services: 0x802019 < HFP AVRCP A2DP Braille ACL >`。
- HFP 串口 `/dev/cu.EDIFIERClearCall200`：可 `open`，45s 内 `read` **0 字节**（AT 通道被系统 bluetoothd 独占）。
- CoreAudio：默认输出设备 `volm / outp / element 1` 可读可写（0.0–1.0，实测 0.6929）。

## 5. 对驱动触发源的映射建议

现有 7 个触发源与真实硬件对照：

| 触发源 | 物理来源（真实） | 当前映射 | 状态 |
|---|---|---|---|
| `volp:click` | ＋ 键单击 | `hid_send F14` | ✅ 可触发（音量观测通道） |
| `volm:click` | − 键单击 | `notify "音量减"` | ✅ 可触发（音量观测通道） |
| `volp:long` | ＋ 键长按 = **上一曲** | `ptt_hold` | ⚠️ 语义不符且当前不可触发 |
| `call:click` | 通话键单击（仅通话中） | `hid_send F13` | ❌ 非通话态无事件 |
| `call:double` | 通话键双击（回拨/切换） | `notify` | ❌ 同上 |
| `call:long` | 通话键长按 2s（拒接） | `notify` | ❌ 同上 |
| `mute:click` | **电源键单击（通话中）** | `obs_toggle_mute` | ❌ 系统独占，且来源标注错误 |

**建议修正**（改动需走 `openspec/changes/`）：

1. 把 `mute:click` 的来源说明改为「通话中电源键单击」，并在 UI 卡片上标注「通话中 · 系统独占」。
2. `volp:long` 语义改为「＋ 键长按（上一曲）」，动作若要保留 `ptt_hold`，需在 UI 明示这是映射后的行为。
3. 待验证项拆成独立 change：验证 AVRCP Next/Prev 与 Play/Pause 是否能被观测，验证通过后新增 `power:click`（播放/暂停）触发源。
4. UI 的「通话键」卡片保留（通话中可用），但需明确「非通话状态无上报，不可自定义」。
