# 开发路线与验收标准（3 批交付）

## 为什么是 3 批，而不是 6 步或一次全量

分批的依据不是"功能模块"，而是**依赖边界**：

| 依赖类型 | 影响 | 对应批次 |
|---|---|---|
| 无硬件依赖，纯逻辑 | 可以一次写完 | **批 1** |
| 卡在抓包（mute 走哪条 AT、阈值分布、忙灯可写性） | 写死了也只能猜 | **批 2** |
| 卡在环境权限（uinput / 虚拟麦 / OBS） | 失败不是代码 bug，要能和逻辑错误分开看 | **批 3** |

一次全量交付的三个现实问题：
1. AI 单次输出有长度上限，13 条命令 + 7 模块 + 5 动作一次生成容易截断、命名前后不一致。
2. 方差太大：真机上一次崩，要在 800 行里定位是哪一层。
3. 不可回滚：parser 判断错了本该回退一个模块，全量只能整体推倒。

> 原则：**每一批交付时，程序都是"可运行 + 可验收"的完整状态**，不交半成品。

| 批次 | 内容 | 依赖 | 交付形态 |
|---|---|---|---|
| **批 1 · 整机可跑** | 骨架 + 状态机 + 规则 + ASCII 界面 + 全部命令 + 单实例锁 + `--log` + `doctor` 骨架 | 无硬件 | `test trigger=...` 跑通全链路，界面与 spec 逐条对齐 |
| **批 2 · 硬件接入** | btmon/BlueZ 采集 + parser（手势判定、边沿事件）+ learn 模式 + 忙灯探测 | 需要抓包 | 真机按键 → 正确 trigger；learn 里能逐个验键 |
| **批 3 · 执行器 + 收口** | 5 个动作 + 异常路径 + 性能 + spec 对账 + 验收清单 | 需要权限/OBS | 真机按住说话可用，`doctor` 全绿 |

## 技术选型（批 1 开场就定）

| 方案 | 优点 | 缺点 |
|---|---|---|
| Python + Rich + prompt_toolkit | 迭代最快，dbus-python / pyudev 生态齐全，UI 库成熟 | 常驻内存略高，asyncio 与线程需小心混用 |
| Go + bubbletea / tview | 单文件分发、并发天然好（goroutine 处理采集） | BlueZ D-Bus 需 godbus，HFP AT 解析要自己写 |
| Rust + ratatui + zbus | 最稳、最低资源、类型安全 | 上手与迭代成本最高 |

> 倾向：**Python 起步**（先把界面 + learn 跑通），若要交付常驻工具再考虑 Go。
> 无论选哪个，模块边界按 `CLAUDE.md` 划分，不要耦合。

## 批 1 验收（无硬件，全部可用 `test` 驱动）

- [ ] 状态栏四字段正确渲染；learn 模式有提示行 + 倒计时
- [ ] 7 条触发源带序号 + `(HFP, only in call)` 备注
- [ ] 规则区随 `set` 即时刷新；非法动作 / 越界序号给 ERR；`save` 后 `dirty=false`
- [ ] `test trigger=volp:long` 走完 EVENT → 规则匹配 → ACTION（动作可先占位打日志）
- [ ] 手势判定：未绑 double 的键 release 即刻触发；绑了 double 的等窗口；长按不产 click
- [ ] 13 条命令全部可用：`list / set / learn / normal / test / save / reload / state / doctor / debug / export feed / help / quit`
- [ ] `learn` 期间零动作执行，30s 超时回 normal，重复进入只重置倒计时
- [ ] 重复启动被单实例锁拦住；陈旧锁能自动接管
- [ ] `quit` / Ctrl-C 走完整清理路径，不残留锁文件
- [ ] `--log` 能落盘；非 TTY 自动降级为逐行日志
- [ ] 事件流环形缓冲 200 行；20 事件/秒下界面不卡、输入延迟 <100ms
- [ ] 配置文件损坏时备份 + 回退默认，不崩溃

> 批 1 的 `doctor` 只实现"不依赖蓝牙/权限探测"的项（配置、实例锁），其余留 ⚠️ 未探测。

## 批 2 验收（需要真机 + 抓包）

前置：`docs/蓝牙调试指南.md` 的采样表至少跑完 AVRCP 与 HFP 两轮。

- [ ] 按 MAC 绑定目标设备，其他蓝牙耳机按键被忽略
- [ ] 音量单击 / 长按 → `volp:click` / `volp:long`；音量减 → `volm:click`
- [ ] 通话键单击 / 长按 / 双击 → 三个 trigger 正确，且互不重复产出
- [ ] 长按成立后抬起不再产生 click；双击窗口内不产生两条 click
- [ ] `mute:click` 仅在 `call_state != idle` 时出现；空闲按静默丢弃**且不算错误**
- [ ] `call_state`：ringing / active / held / idle 四种都能正确反映到状态栏
- [ ] 一拖二场景下事件不串台（按连接句柄过滤）
- [ ] 断连后自动重连，界面标注 `BT: OFFLINE`，恢复后自动继续监听
- [ ] learn 模式：逐个按键出现 `[LEARN ✅]`；无法解析的报文出现 `[LEARN ⚠] unknown pdu`
- [ ] 忙灯探测结果缓存；不可控时降级 `BusyLight control unsupported`，不重试不刷屏
- [ ] btmon 抓包样本作为 fixtures 的单元测试通过

## 批 3 验收（需要权限 / 外部服务）

- [ ] `ptt_toggle`：虚拟麦缺失时 ERR 且 `ptt_state` 不变
- [ ] `ptt_hold`：按住开麦、松开停麦；断连 / 超 `ptt_hold_max_sec` / 退出时强制停麦
- [ ] toggle 推流中按 hold 绑定键 → `ERR ptt busy`，不叠加
- [ ] `actions.ptt.source` 支持 `default` / `headset`；推流中拔麦 → 停麦 + ERR
- [ ] `hid_send`：`/dev/uinput` 无权限时 ERR 带可复制修复命令
- [ ] `obs_toggle_mute`：连不上 ERR 不崩溃；连上能正确翻转
- [ ] `notify`：通知服务不可用时降级为事件流提示，不报错
- [ ] `doctor` 九项全量可用，结论分级（✅/⚠️/❌）与"先修哪项"正确
- [ ] 异常路径全覆盖：蓝牙断开、OBS 未启动、配置损坏、动作抛异常、快速连按
- [ ] 7 份 spec 逐条对账，输出 `docs/验收清单.md`，无未解释的偏离

## 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| `mute` 空闲不上报 | 用户以为程序坏了 | 界面备注 + learn 如实无反馈 + 文档说明 |
| Linux 上 HFP AT 不易取到 | 静音/接听类事件缺失 | 以 btmon HCI 解析为主路径；必要时降级只支持 AVRCP 触发源 |
| AVRCP 默认行为拦不住 | 用户预期落空 | 决策 A：并存；界面与文档如实说明，推荐绑 `volp:long`/`volm:click`/`call:long` |
| 一拖二链路切换 | 事件串台 | 按连接句柄过滤 |
| 虚拟麦依赖 PulseAudio | ptt 不可用 | `doctor` 先查设备存在性，缺失给明确 ERR |
| OBS 版本接口差异 | 静音动作失败 | 固定 WebSocket v5，配置可改 |
| 忙灯可能不可写 | learn 缺物理反馈 | 能力探测 + 降级文案，不当作失败 |
