# 界面设计（ASCII 原型与布局规则）

> 对应规范：`openspec/specs/terminal-ui/spec.md`
> 本文是视觉原型，规范冲突时以 spec 为准。

## 1. 屏幕分区与刷新策略

整屏固定分 6 个区，各区的刷新频率不同，这样既有"实时感"，又不会因为高频事件导致整屏重绘闪烁。

```
┌──────────────────────────────────────────────────────────────┐
│ ① 标题栏                                                      │  静态：启动渲染一次
├──────────────────────────────────────────────────────────────┤
│ ② 状态栏  CALL / MIC / PTT / MODE                             │  事件驱动：状态变化才刷
├──────────────────────────────────────────────────────────────┤
│ ③ 提示行（仅 learn / 蓝牙离线时出现，否则不占行）              │  状态驱动
├──────────────────────────────────────────────────────────────┤
│ ④ 触发源区（7 行，带序号 + 硬件限制备注）                      │  静态：启动渲染一次
├──────────────────────────────────────────────────────────────┤
│ ⑤ 规则区（7 行）                                              │  set / save / reload 后刷
├──────────────────────────────────────────────────────────────┤
│ ⑥ 事件流区（环形缓冲 200 行，新行追加在底部）                  │  增量追加，≤10Hz 合并
├──────────────────────────────────────────────────────────────┤
│ ⑦ 命令行  > _                                                 │  输入时局部重绘
└──────────────────────────────────────────────────────────────┘
```

渲染原则：
- 只重绘变化的区，不整屏 clear（避免闪屏）
- 事件流是**追加式**，满了丢最旧的一行
- 输入过程中后台事件照常追加，**但不清空用户已输入的命令行内容**
- 非 TTY 环境放弃光标控制，退化为逐行纯文本（见 §7）

## 2. 正常模式（idle，无通话）— 默认首屏

```
=============================================================
 ClearCall200 Client | follow OpenSpec
=============================================================
 📞 CALL: [IDLE] | MIC: [OPEN] | PTT: [OFF] | MODE:[NORMAL]
-------------------------------------------------------------
 Bindable Triggers:
 [0] mute:click      (HFP, only in call)
 [1] call:click
 [2] call:long
 [3] call:double
 [4] volp:click
 [5] volp:long
 [6] volm:click
-------------------------------------------------------------
 Rules:
 0: mute:click      → obs_toggle_mute
 1: call:click      → hid_send F13
 2: call:long       → notify"长按通话键"
 3: call:double     → notify"双击通话键"
 4: volp:click      → hid_send F14
 5: volp:long       → ptt_hold
 6: volm:click      → notify"音量减"
-------------------------------------------------------------
 Feed:
 (空)
-------------------------------------------------------------
 Commands: list | set N ACTION | learn | normal | test TRIG | save | reload
           state | doctor | debug on|off | export feed | quit
> _
```

设计说明：
- 触发源区的那行 `(HFP, only in call)` 是**硬件事实的常驻声明**，用户第一次看到就知道 0 号键有前提，不用去翻文档。
- 规则区是"编号 ↔ 触发 ↔ 动作"三段对齐，因为 `set N ACTION` 靠编号操作，编号必须在同一列。
- 事件流初始显示 `(空)` 而不是留白，避免用户以为界面坏了。

## 3. 正常模式（通话中 + 推流中 + 有事件）

```
=============================================================
 ClearCall200 Client | follow OpenSpec
=============================================================
 📞 CALL: [ACTIVE] | MIC: [MUTED] | PTT: [ON·hold] | MODE:[NORMAL]
-------------------------------------------------------------
 Bindable Triggers:
 [0] mute:click      (HFP, only in call)
 ...
-------------------------------------------------------------
 Feed:
[20:14:02] > STATE call_state=ringing mic_mute=0
[20:14:06] > STATE call_state=active mic_mute=0
[20:14:09] > EVENT trigger=volp:long
[20:14:09] > ACTION action=ptt_hold → ptt_state=1
[20:14:11] > EVENT trigger=mute:click
[20:14:11] > ACTION action=obs_toggle_mute → muted=1
[20:14:11] > STATE call_state=active mic_mute=1
[20:14:18] > ACTION action=ptt_hold → ptt_state=0
[20:14:24] > STATE call_state=idle mic_mute=0
-------------------------------------------------------------
> _
```

设计说明：
- `PTT: [ON·hold]` 把模式标出来，用户一眼能分辨"我按一下开的"还是"我正按着开的"。
- `EVENT` 与 `ACTION` 成对出现，中间没有别的噪音，用户能顺着看"我按了什么 → 触发了什么"。
- `MIC` 反映的是**耳机侧**静音状态；和 PTT 是两件事，所以两个字段并列而不是合并。

## 4. 学习/测试模式（核心交互）

```
=============================================================
 ClearCall200 Client | follow OpenSpec
=============================================================
 📞 CALL: [ACTIVE] | MIC: [OPEN] | PTT: [OFF] | MODE:[LEARN]
 ⚠️ LEARN MODE ACTIVE: 按键只会检测、不执行动作 | 12s auto exit
-------------------------------------------------------------
 Bindable Triggers:
 [0] mute:click      (HFP, only in call)
 [1] call:click
 [2] call:long
 [3] call:double
 [4] volp:click
 [5] volp:long
 [6] volm:click
-------------------------------------------------------------
 Rules (bypassed):
 0: mute:click      → obs_toggle_mute
 ...
-------------------------------------------------------------
 Feed [LEARN DETECT]:
> [LEARN ✅] trigger=call:click        → BusyLight blink ✨
> [LEARN ✅] trigger=call:long         → BusyLight blink ✨ (waited double window)
> [LEARN ✅] trigger=volp:long         → BusyLight blink ✨
> [LEARN ✅] trigger=mute:click        → BusyLight blink ✨
> [LEARN ⚠] unknown pdu: cid=0x0041 op=0x7c
> [LEARN ✅] trigger=volm:click        → BusyLight control unsupported
-------------------------------------------------------------
 Commands: normal (退出) | set N ACTION (退出后配置) | help
> _
unknown=1 | detected=5/7
```

设计说明（这是这一屏最关键的信息密度）：
- **倒计时放在提示行尾部**（`12s auto exit`），用户随时知道还剩多久，不会突然被切走而困惑。
- 规则区标 `(bypassed)`，明确说明"规则在这儿但没生效"，避免用户误以为按键坏了。
- 三种反馈并列，视觉上能直接区分：
  - `✅ + BusyLight blink ✨` = 识别成功且灯也闪了
  - `✅ + unsupported` = **识别成功、但耳机灯不可控**（不是失败，别误判）
  - `⚠ unknown pdu` = **耳机发了包、我们不认识**（该去抓包逆向）
  - 什么都不出现 = **耳机根本没发包**（0 号键空闲时就是这种）
- 底部统计 `detected=5/7 | unknown=1`，把"这轮测试到底验了几个键"量化，比翻日志快。

## 5. 蓝牙离线状态

```
=============================================================
 ClearCall200 Client | follow OpenSpec
=============================================================
 📞 CALL: [IDLE] | MIC: [OPEN] | PTT: [OFF] | MODE:[NORMAL]
 ⚠ BT: OFFLINE (last seen 20:14:24) — 仅 test 命令可用
-------------------------------------------------------------
 Feed:
[20:16:01] > ERR device offline: 未找到 E8:AA:BB:CC:DD:EE
[20:16:01] > STATE device_online=0
-------------------------------------------------------------
> test trigger=volp:long
> EVENT trigger=volp:long
> ACTION action=ptt_hold → ERR ptt source unavailable
```

设计说明：
- 离线时**程序不退出**，而是把提示行换掉，并明确告知"还能用 test"。
- 状态栏保留最后一次已知值（不置空），因为它比"全空"更有参考意义。

## 6. `doctor` 自检输出（全屏一次性打印）

```
=============================================================
 doctor — 环境自检
=============================================================
 [1] bluetooth service        ✅ active (bluez 5.66)
 [2] adapter present          ✅ hci0  EDR/BLE
 [3] target device online     ✅ E8:AA:BB:CC:DD:EE (ClearCall200)
 [4] hfp/avrcp reachable      ✅ MediaControl1 / HFP AG
 [5] /dev/uinput writable     ❌ permission denied
     └ 修复：sudo usermod -aG input $USER && 重新登录
            或 udev: KERNEL=="uinput", GROUP="input", MODE="0660"
 [6] virtual mic device       ✅ clearcall200_sink (PulseAudio)
 [7] obs websocket            ⚠️ 127.0.0.1:4455 连接被拒
     └ 说明：不影响基础功能，仅 obs_toggle_mute 不可用
 [8] busylight capable        ⚠️ unknown (尚未探测)
     └ 说明：learn 模式将只输出文字反馈
 [9] single instance lock     ✅ /run/user/1000/clearcall200.lock
-------------------------------------------------------------
 结论：3 项可用 / 2 项降级 / 1 项需修复
 建议先修复 [5]，否则 hid_send 全部失效。
=============================================================
```

设计说明：
- 分三级：`✅ 可用` / `⚠️ 降级但能跑` / `❌ 需修复`，并在末尾给**一句结论 + 先修哪项**。
- 每条失败都带**可直接复制的修复命令**，不写"请检查权限"这种无效提示。

## 7. `debug on` 原始报文流（逆向用）

```
> debug on
> [DBG] <- L2CAP cid=0x0041 avrcp PASS_THROUGH op=0x41(vol+) state=press
> [DBG] <- L2CAP cid=0x0041 avrcp PASS_THROUGH op=0x41(vol+) state=release  t=1480ms
> [DBG] <- RFCOMM  AT+CMUT=1                                     during call
> [DBG] <- HFP     +CIEV: call=1
> [DBG] !! unknown: RFCOMM AT+VGS=7
```

设计说明：
- `[DBG]` 前缀避免与业务事件混淆；`!! unknown` 单独标记，方便直接 grep 出"待逆向的指令"。

## 8. 非 TTY 降级输出（重定向到文件 / 管道）

```
$ clearcall200 --log feed.log | tee
[20:14:02] STATE call_state=ringing mic_mute=0
[20:14:06] STATE call_state=active mic_mute=0
[20:14:09] EVENT trigger=volp:long
[20:14:09] ACTION action=ptt_hold → ptt_state=1
[20:14:11] EVENT trigger=mute:click
[20:14:11] ACTION action=obs_toggle_mute → muted=1
```

设计说明：
- 不带任何框线与光标控制，每行一条记录，可直接 `grep EVENT` / `awk` 统计。
- 命令输入在非 TTY 下不可用（没有 stdin 交互），但配置文件仍可生效。

## 9. 状态机（三张关键图）

### 9.1 模式

```
        learn
 normal ──────────► learn
    ▲                 │
    │  normal 命令    │
    ├─────────────────┤
    │  30s 超时       │
    └─────────────────┘
```

### 9.2 通话状态（HFP 上报）

```
 idle ──RING──► ringing ──接听──► active ──保持──► held
   ▲               │                │  ▲             │
   │               │拒接/未接        │  └──恢复───────┘
   └───────────────┴────────────────┘
            挂断 / 通话结束
```

### 9.3 推流与强制停麦

```
        ptt_toggle                edge press
 ptt=0 ───────────────► ptt=1(toggle)  ◄─── ptt_hold
   ▲                        │
   │  ptt_toggle            │ 断连 / release / 超时 / 退出
   └────────────────────────┘
              （一律强制停麦）
```

### 9.4 按键手势判定

```
        按下
          │
          ├── 持续 ≥ long_press_ms ──► LONG（立即触发，不再产 click）
          │
          └── 释放（未达长按）
                 │
                 ├── 该键绑定了 double ──► 等 double_click_ms
                 │        ├── 窗口内再按 ──► DOUBLE
                 │        └── 超时      ──► CLICK（标注 waited double window）
                 │
                 └── 该键未绑定 double ──► CLICK（立即）
```

## 10. 交互闭环示例（用户视角完整走一遍）

```
1) 启动            → 首屏（§2），看到 7 个触发源与默认规则
2) 输入 doctor     → 发现 /dev/uinput 无权限（§6），按提示修复
3) 输入 learn      → 进入学习模式（§4），倒计时开始
4) 依次按 7 个键   → 逐个出现 [LEARN ✅]，mute 键需通话中才亮
5) 发现 unknown    → [LEARN ⚠] 出现，说明有未解析报文，去抓包
6) normal 退出     → 回到正常模式
7) set 5 ptt_hold  → 把音量+长按改成按住说话
8) save            → 落盘，dirty=false
9) 实际使用        → 通话中按住音量+，状态栏 PTT 变 [ON·hold]，松手变 [OFF]
```

## 11. 桌面挂件（常驻置顶浮层）

> 定位：**状态镜像 + 按键反馈器**。不是主界面，不承载配置，不复制规则逻辑。
> 规范：`openspec/specs/desktop-widget/spec.md`

### 11.1 键位工具条（`--widget bar`，默认形态）

尺寸固定 **320×46 px**，无边框、半透明、默认停靠屏幕右上角（右 24px / 上 48px），
空白处按住可拖动，关闭即走统一清理（停推流 + 释放锁）。

常态（空闲、蓝牙未接入）：

```
┌──────────────────────────────────────────────────────┐  ← 320×46
│ ● IDLE   [静] [话] [＋] [－]              话·长按  ▁▁▁▁ │
└──────────────────────────────────────────────────────┘
  │         │    │    │    │                 │      └ PTT 细条（46×6，未推流时只剩底线）
  │         │    └────┴────┴─ 4 个键位胶囊   └ 最近一次识别结果（1.2s 后自动消退）
  │         └ 通话状态缩写：IDLE / RING / ACTV / HELD / DIAL
  └ 连接指示点：离线灰 / 在线绿 / 学习模式琥珀闪烁
```

按下 `call` 键瞬间（边沿 press 触发点亮，release 后 ≤250ms 回落）：

```
┌──────────────────────────────────────────────────────┐
│ ● ACTIVE  [静] ▓话▓ [＋] [－]             话·长按  █████ │
└──────────────────────────────────────────────────────┘
                ↑ 高亮填充 #4ea1ff，深色字     ↗ PTT hold 进度随按住时长增长
```

学习模式（只检测不执行）：整条边框转琥珀色，提示点闪烁：

```
╔══════════════════════════════════════════════════════╗  ← 边框 #ffb74d
║ ● LEARN   [静] [话] [＋] [－]            LRN 只检测  ▁▁ │
╚══════════════════════════════════════════════════════╝
```

### 11.2 桌宠（`--widget pet`）

尺寸 **88×88 px**，表情随状态切换，气泡显示最近一次识别结果：

```
┌────────┐
│ 话·长按 │  ← 气泡（1.2s 后消失）
│        │
│   🐰   │  ← idle 🐰 / 按键 😮 / 推流 🎙️ / 静音 🤐 / 通话 📞
└────────┘
```

### 11.3 状态色表（两种形态共用）

| 语义 | 取值 | 颜色 |
|---|---|---|
| 空闲 | `call_state=idle` | 灰 `#7c828b` |
| 来电 | `ringing` | 琥珀 `#ffb74d` |
| 通话中 | `active` | 绿 `#7bd88f` |
| 保持 / 拨号 | `held` / `dialing` | 蓝 `#4ea1ff` |
| 麦克风静音 | `mic_mute=1` | 琥珀 `#ffb74d`（静音胶囊变字色） |
| 按下点亮 | `edge press` | 蓝 `#4ea1ff` 填充，深色字 |
| 学习模式 | `app_mode=learn` | 边框琥珀 + 指示点闪烁 |
| PTT 进度 | `ptt_state=1` | 蓝填充；到达 `ptt_hold_max_sec` 转琥珀 |

### 11.4 交互约定

- 点击任一键位胶囊 = 注入一次该键的 `click`（`EVENT trigger=xxx:click (widget)`），用于干跑验证
- 挂件内**不放输入框**：复杂配置仍在终端模式执行（避免抢焦点、避免两套命令入口）
- 关闭窗口 = `quit`：停推流 → 释放单实例锁 → 进程退出

### 11.5 主设置窗口（`--ui`）

承担"自定义按键"本身：7 条规则逐行可改，动作下拉 + 参数框 + 测试按钮；
参数区可改长按/双击阈值、学习超时、PTT 上限与音源。关闭主窗口只隐藏（保活），
点挂件上的 ⚙ 可唤回；关闭挂件才真正退出。
