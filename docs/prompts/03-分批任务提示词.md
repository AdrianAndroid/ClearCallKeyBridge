# 提示词 03 · 分批任务提示词（3 批，按顺序用）

> 分批依据是依赖边界：批 1 无硬件依赖（一次写完）、批 2 卡抓包、批 3 卡环境权限。
> 每批交付都必须是"可运行 + 可验收"的完整状态。

## 批 1 · 整机可跑（无硬件，全部用 test 驱动）

```
执行【批 1：整机可跑】。目标：不依赖任何蓝牙硬件，让程序用 test 命令就能完整演示与验收。

0. 开场先定技术选型：Python(rich/prompt_toolkit) vs Go(tview/bubbletea) vs Rust(ratatui)，
   对比在 Linux 下抓 BlueZ/btmon 的难度，给出推荐与理由，等我确认后再动手。
1. 骨架：按 CLAUDE.md 的模块划分建目录（bluetooth / parser / rules / state / executor / ui /
   busylight / runtime / diag），每个模块先留接口与 docstring，不写业务。
2. 配置：启动加载 config/rules.json；不存在则从 config/rules.example.json 生成；
   损坏则备份为 .bak 并回退默认。配置项含 timing / learn_timeout_sec / ptt_hold_max_sec / ui。
3. state：实现 app_mode / call_state / mic_mute / ptt_state / ptt_mode / device_online / learn_remain；
   状态变化才输出 STATE 行，相同状态不重复刷。
4. rules：7 条固定序号规则；list / set N ACTION / save / reload；
   非法动作与越界序号给 ERR；reload 在 dirty 时要求确认。
5. ui：按 docs/界面设计.md 的分区渲染（标题栏/状态栏/提示行/触发源/规则/事件流/命令行），
   只重绘变化区；事件流环形 200 行；≤10Hz 合并刷新；非 TTY 降级为逐行日志。
6. 命令全部可用：list / set / learn / normal / test / save / reload / state / doctor / debug / export feed / help / quit。
7. learn 模式：跳过规则匹配与动作执行，输出 [LEARN ✅] / [LEARN ⚠]，30s 倒计时（提示行显示剩余秒数），
   重复进入只重置倒计时；忙灯先用 mock 实现（可被配置成"不可控"以走降级分支）。
8. runtime：单实例锁（$XDG_RUNTIME_DIR/clearcall200.lock，陈旧锁自动接管）；
   quit / SIGTERM / SIGINT 统一清理；--log <path> 落盘，写失败不致命。
9. 手势判定（先用 test 注入 press/release 时间戳验证）：未绑 double 的键 release 即刻触发；
   绑了 double 的等窗口；长按到阈值即时触发且不再产 click；parser 产出内部 edge press/release。
10. executor 本批只做占位实现（打日志 + 更新状态），真实执行留到批 3。

验收：docs/开发路线.md 的"批 1 验收"清单逐条勾选，并附自测步骤。
不要接任何蓝牙代码；不要碰 OBS / uinput / PulseAudio 的真实调用。
```

## 批 2 · 硬件接入（需要抓包）

```
执行【批 2：硬件接入】。前置：我已按 docs/蓝牙调试指南.md 抓完包（或我先给你样本）。

先给方案再写代码：
1. 你打算用 BlueZ D-Bus（MediaControl1 / HFP）还是 btmon HCI 解析，还是两者结合？各自能覆盖哪些 trigger？
2. HFP AT 事件在 Linux 上具体从哪个点取，若取不到，降级策略是什么？
3. 一拖二时按什么标识隔离链路？

实现要求：
4. 采集跑在独立线程/协程，不阻塞 UI；断连自动重试，UI 标注 BT: OFFLINE。
5. 按 MAC 绑定目标设备，其他耳机按键必须被忽略。
6. parser 把报文翻成 7 个 trigger + call_state + mic_mute；
   空闲时 mute 静默丢弃且不报错（硬件事实，不得伪造）。
7. 无法识别的报文：learn 模式输出 [LEARN ⚠] unknown pdu: ...；normal + debug off 时静默。
8. learn 模式接入真实采集：逐键检出、长按不重复产 click、标注 (waited double window)。
9. busylight：做能力探测并缓存；不可控时输出 BusyLight control unsupported，不重试不刷屏。
10. 用抓包样本做 fixtures，为每个 trigger 写单元测试。

不要在本批实现真实动作执行（仍用占位）；不要自行扩展触发源或新动作。
```

## 批 3 · 执行器 + 收口（需要权限 / 外部服务）

```
执行【批 3：执行器 + 收口】。

A. 落地 5 个动作（替换批 1 的占位）：
1. ptt_toggle：接虚拟麦（PulseAudio/PipeWire），设备缺失 ERR 且不改 ptt_state。
2. ptt_hold：依赖 edge press/release；press 开麦、release 停麦；
   断连 / 超过 ptt_hold_max_sec / 退出 一律强制停麦；toggle 推流中触发 → ERR ptt busy 不叠加。
3. hid_send：uinput 发送键码；非法键码 ERR；/dev/uinput 无权限时 ERR 带可复制修复命令。
4. obs_toggle_mute：OBS WebSocket v5，配置取 actions.obs；连不上 ERR 不崩溃。
5. notify：notify-send，不可用降级为事件流提示。
另：actions.ptt.source 支持 default / headset；推流中源设备拔出 → 停麦 + ERR。

B. doctor 补齐九项检查（蓝牙服务/适配器/设备在线/HFP 可达/uinput/虚拟麦/OBS/忙灯/实例锁），
   分 ✅ / ⚠️ / ❌ 三级，给修复命令与"先修哪项"的结论。

C. 收口：
6. 异常路径全覆盖：蓝牙断开、OBS 未启动、配置损坏、动作抛异常、快速连按。
7. 性能：20 事件/秒下界面不卡，输入延迟 <100ms。
8. 与 7 份 spec 逐条对账，输出 docs/验收清单.md，列出"未实现/偏离"（先报告，不要自行补功能）。
```

```
本批结束后请输出：
1. 改动文件清单（新增/修改）；
2. 本批验收清单逐条勾选结果（✅/⚠️/❌ 并说明）；
3. 遗留项与建议下一批做的事（不要越批实现）。
```
